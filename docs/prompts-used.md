# Prompts Used

> A reconstruction of the cumulative prompting that produced the prototype at

> from the actual session — not a verbatim chat log, but a faithful

## 1. Business & product brief (given first, as context)

```
We're building ReThread AI — an AI-powered fashion-waste recycling
marketplace for Nigeria. Problem: tailors and fashion houses throw away
fabric scraps daily; fashion students/designers/hobbyists can't easily find
or afford small quantities of usable material. ReThread connects the two
sides using AI.

Core loop: a supplier uploads a photo of a fabric scrap (+ optional
dimensions/weight) → AI identifies the material, color, and condition → AI
suggests 2-3 zero-waste products that could be made from it (tote bags,
bandanas, patchwork pieces, etc., not full garments unless the scrap is
clearly big enough) → the listing can be posted to a marketplace where
buyers browse and reserve.

Revenue model: transaction commission, premium subscription, ads, bulk
listing fees, future premium AI tools.

Target users: Nigerian tailors/fashion houses (suppliers) and fashion
students/designers/upcycling hobbyists (buyers).

This is a 2-day hackathon prototype, not a production build. Budget: $3
credit on fal.ai, $5 credit on the Claude API platform (console.anthropic.com,
not a claude.ai chat subscription). I'm a 6-year software developer, so skip
beginner explanations. A landing page + dashboard mockup already exists,
built with Lovable, single HTML file with Tailwind via CDN, fully faked (no
real backend, no real AI — everything is a setTimeout and hardcoded data).
It uses a warm linen-beige + olive-green ("forest/mint") color palette —
keep that exact accent, don't redesign it.
```

A separate, more elaborate prompt (generated by another AI chat the user
consulted) proposed a single-file Node/Express + React-via-CDN app with a
"Computer Vision Simulation Layer" that faked TensorFlow/MobileNet
classification with hardcoded confidence scores, an in-memory "database," and
an Apple/Linear-style black-and-mint glassmorphic redesign. The user
explicitly instructed: **disregard that advice as a literal spec** — it was
treated as background only, not followed.

## 2. The actual build instruction (consolidated)

```
Don't fake the AI — build it for real, but keep it appropriately scoped for a
2-day prototype:

- Real backend: Node/Express, serving both the API and the existing static
  dashboard HTML as one deployable process.
- Real fabric classification: send the uploaded photo to Claude's vision API
  (multimodal image input). Return material type, color profile, condition,
  a confidence score, and 2-3 suggested products with descriptions and
  estimated Naira values. Factor in user-provided dimensions/weight if given.
- Real concept image generation: send the fabric photo + chosen product idea
  to fal.ai. Find/use a model capable of taking a reference image and
  transforming it into a photorealistic product shot (or a model wearing the
  garment) while preserving the fabric's actual color and pattern — confirm
  this is technically possible on fal before assuming it.
- A basic marketplace store (in-memory is fine for a 2-day demo) that
  listings can be POSTed to and GETed from.
- Add input fields for fabric dimensions (length x width) and weight to the
  upload form — these should actually flow into the AI calls and the
  marketplace listing, not just sit on screen.
- Add a "Coming Soon" section/badges for the features described in the
  business plan's future-features list (AI Chat Assistant, Voice Assistant,
  AI Pattern Generator / DXF export, Advanced Analytics, Supplier
  Verification, Mobile App, Integrated Payments, Notifications) so nothing
  unbuilt is presented as real in front of judges.
- Replace every fake preset/mock result in the existing dashboard with either
  a real AI call or an honest "Coming Soon" placeholder — don't leave
  hardcoded fake outputs that could be mistaken for real AI results.
- Keep the existing landing page's visual design and color accent as-is;
  light visual polish is fine, no redesign.
- Store the provided API keys (Anthropic, fal.ai) in a gitignored .env file
  immediately — never echo them back in chat or commit them.
- Test both AI endpoints end-to-end with the real keys before considering the
  backend done — don't just write the code and assume it works.
- Set up a docs/ folder as the single home for all project documentation
  (this file included), plus a CLAUDE.md pointer at the project root so a
  fresh chat picks up context automatically, plus a docs/STATUS.md living
  document and a /handoff command that rewrites it at the end of each working
  session — the user manages context by closing chats and starting new ones,
  and relies on these docs (not chat history) for continuity.
- Create a Claude Code skill that generates/refreshes a plain-English,
  jargon-free explainer of whatever is actually built (not the plan — the
  real current state), written for a non-technical co-founder who needs to
  be able to explain the demo to judges herself.
```
