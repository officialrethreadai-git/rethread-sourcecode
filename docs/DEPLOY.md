# Deploying to Render

This is a single Node/Express **Web Service** — it serves both the API
(`/api/*`) and the static frontend (`frontend/`) from one process, so there's
only one Render service to create (not a separate static site + API).

## One-time setup (you do this in Render's dashboard — not here)

1. Push this repo to GitHub (already has a remote: `origin`).
2. In the Render dashboard: **New > Blueprint**, connect the GitHub repo.
   Render reads `render.yaml` at the repo root and pre-fills the service
   (root dir `server/`, build `npm install`, start `npm start`, free plan).
3. Render will prompt you for the env vars marked `sync: false` in
   `render.yaml` — paste them directly into Render's dashboard fields, **not**
   into a chat or a file that gets committed:
   - `ANTHROPIC_API_KEY`
   - `FAL_KEY`
   - `FAL_ADMIN_KEY` (optional — only needed for the admin balance panel)
   - `ANTHROPIC_ADMIN_KEY` (optional — same)
   - `ADMIN_USERNAME`
   - `ADMIN_PASSWORD_HASH` (a bcrypt hash, not a plaintext password — see
     `server/.env.example` for how to generate one)
   - `ADMIN_SESSION_SECRET` is auto-generated by Render (`generateValue: true`)
     — no need to paste anything for that one.
4. Deploy. Render gives you a public `*.onrender.com` URL.

## After that

Every push to the connected branch auto-deploys. No API key or MCP setup is
needed on our side — Render's GitHub integration handles the connection, and
secrets live only in Render's dashboard.

## Notes

- Free-tier Render web services spin down after inactivity and take ~30-60s
  to wake on the next request — worth doing a warm-up request a few minutes
  before a live demo.
- The in-memory marketplace/admin-access stores reset on every deploy and on
  free-tier spin-down. Fine for this prototype; flag it if that matters for
  judging.
